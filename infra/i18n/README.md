# Переводы лаунчера

Раньше переводы синхронизировались cron-задачей на сервере, и скрипты лежали
рядом с его конфигами. Сервера больше нет — синхронизация живёт в CI.

## Как это работает

`SpikyTeam/meta-launcher/.github/workflows/sync-i18n.yml` раз в сутки:

1. Забирает эти скрипты из ветки `develop` этого репозитория.
2. Ставит `qttools5-dev-tools` ради `lupdate`, `lconvert` и `lrelease`.
3. Скачивает переводы из Prism, сверяет каждый по sha1 и отбрасывает
   непереведённые (порог 90%, настраивается через `I18N_MIN_PERCENT`).
4. Накладывает `ru.ts` поверх `base-ru.ts` и собирает `.class`.
5. Кладёт результат в `static/i18n` репозитория `meta-launcher` и
   пересобирает сайт.

Поэтому `static/i18n` в `meta-launcher` и есть то, что отдаётся игрокам, а
`meta-launcher/static/i18n/index_v2.json` — индекс с sha1 каждого файла.

## Файлы

- `i18n_sync.py` — скачивание, проверка, фильтрация, чистка лишних файлов.
- `i18n_overlay.py` — слияние перевода с исходниками и сборка `.class`.
- `ru.ts` — наш перевод поверх `base-ru.ts`.
- `base-ru.ts` — базовая версия `.ts`, из которой `ru.ts` берёт контекст.
  Если файла нет, `i18n_overlay.py` подсевает его автоматически.

## Пути

Скрипты ничего не знают о серверной раскладке, всё берётся из окружения:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `I18N_SRC_BASE` | `src` | Исходники лаунчера |
| `I18N_DST_DIR` | `/var/www/mc.spiky.team/i18n` | Куда складывать переводы |
| `I18N_BASE_TS_DIR` | — | Каталог с `base-<code>.ts` |
| `I18N_OVERLAY_DIR` | `infra/i18n` | Наши `.ts`-накладки |
| `I18N_WORK_DIR` | `/opt/spikymc-meta/i18n-work` | Временные файлы `lupdate` |
| `I18N_MIN_PERCENT` | `90` | Порог переведённости |

Значения по умолчанию рассчитаны на прежний сервер и нужны только для
локального запуска; в CI пути задаёт сам workflow.

## Локальный прогон

Нужны `qttools5-dev-tools`, `python3` и `requests`.

```sh
I18N_SRC_BASE=../../src \
I18N_DST_DIR=/tmp/i18n-out \
I18N_WORK_DIR=/tmp/i18n-work \
python3 infra/i18n/i18n_sync.py
```
